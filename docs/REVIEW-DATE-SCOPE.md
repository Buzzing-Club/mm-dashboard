# Review 日期筛选与历史保留

- 默认本周，按 UTC+8 周一 00:00 至下周一 00:00，筛选市场结束日期。
- 支持自定义起止日期（包含截止日）和全部历史。没有有效结束日期的已关闭市场仅在全部历史中可见，不猜测结束日期。
- 市场选择器、类别计数、账户 PnL 和阶段 PnL 使用相同的筛选后市场集合。
- 日期筛选不改变单市场生命周期边界，不把本周起点传入成交、决策或 PnL 计算。跨周运行且本周结束的市场仍需要全生命周期数据。
- 切换范围不会删除结束快照、持久化观测或离线汇总。这里不设置七天保留期。

## 尚存的历史读取限制

日期筛选目前作用于看板已加载的市场目录。历史目录入口仍为 `/api/dashboard/history?limit=500`；策略兼容事实入口仍读取全局最近 1000 条目录/决策/成交。日期筛选不能使这些上游结果自动变完整。

完整历史需要策略端提供按市场结束日期分页的历史目录，以及按 condition/account/job 和完整生命周期分页的事实读取或已完成的持久复盘汇总。分页未完成、源记录已清理、观察窗口存在空档时必须继续显示覆盖缺口，不能以零或取消告警冒充完整。

全生命周期订单流毒性已独立改用 `/api/dashboard/review-order-flow` 逐市场分页评分，并将小型汇总原子保存到 `REVIEW_SUMMARY_DIR/order-flow`。它不再受全局 1000 条限制；其他依赖兼容事实入口的指标仍受上述限制。首次打开已结束市场时完成汇总，后续默认读磁盘，24 小时后按访问重新验证；有未完成观察窗时两分钟后重试。更新失败或样本数减少时保留旧汇总。不承诺恢复已清理的原始价格采样，也不删除原有历史。

`mm_strategy_decisions` 属于短期排障记录，不应为本次日期筛选直接取消其清理规则或无界保存高频快照。已经删除的旧采样不能从筛选条件恢复。长期复盘应保留足够的业务事实和阶段汇总；后端可重建的成交按历史接口取回。
